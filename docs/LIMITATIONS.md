# Known limitations

- The experiment runner executes deterministic scenario fixtures, not the LLM agent loop. Results are mock/development evidence only. A separate `POST /api/agent/run` endpoint uses the configured Gemini Interactions or OpenAI Chat Completions tool loop and registered tools, but it is not integrated into paired experiments. Provider loop and gateway behavior are covered with mocked provider tests; live provider/JEV credentials have not been verified here.
- JEV is the default semantic decision engine for every schema-valid protected agent action and AURA-mode experiment decision. Local deterministic invariants remain hard vetoes. The adapter has mocked HTTP coverage, but has not been live-tested with an OpenRouter key. `DECISION_ENGINE=local` remains a development fallback. Detailed per-decision cost aggregation for fixture experiments remains incomplete.
- Experiment state uses in-process FastAPI background tasks. It is intended for a single local process and does not support durable job recovery or concurrency controls.
- The monitoring dashboard includes persisted action summary/activity, filtered action rows with detail timelines, derived alerts, a pending approval queue, and bounded CSV export. Agent Event Logs adds structured, SQL-filtered lifecycle events, indexed trace/action fields, chronological trace inspection, and CSV export capped at 200 events. Authentication and reviewer roles are still absent, so these views and approval APIs are local-development-only. The older action list filters over in-process results; structured event log filters run in SQL. Older audit records remain readable but are not backfilled into new indexed columns.
- JEV uncertainty can create a pending approval. The decision endpoint checks exact arguments, validates the registered tool again, and executes only after a one-time backend state transition; rejection does not execute. Multi-process approval races are not production hardened.
- No authentication, CSRF protection, production hardening, managed migration framework, statistical confidence intervals, persistent model invocation ledger, or browser-level smoke test. SQLite receives additive startup columns for action correlation and decision metadata. JEV thresholds are provisional and require calibration.
- Gemini integration uses the Google Gen AI SDK and has mocked tool-loop tests but has not been live-tested with a Gemini API key. Free-tier limits vary by model and may change; consult current Google AI Studio terms before use.
- Pricing is unknown unless independently configured; mock runs report unavailable token usage.
- Agent Query Testing provides 31 versioned scenarios across categories A–H. Runnable scenarios call the actual configured agent and gateway only after an explicit UI action and a configured shared `AURA_TEST_RUN_TOKEN`; full-suite runs can incur model/JEV charges. Deterministic-only fault-injection, reviewer-action, and 50-read rate-limit scenarios are reported as skipped. The app has no per-session read-rate policy, authenticated user identity, or reviewer-role authorization; the shared test token is not a substitute. Tool history is preserved across calls inside one agent request but not between separate scenario requests. Test results live in separate tables and related execution/audit records are tagged; production monitoring filters tagged events.
- Query-test run dispatch uses FastAPI in-process background tasks and a single-process active-run guard; it does not provide durable job recovery or cross-worker locking. A stopped process may leave a run marked queued/running until manually reviewed. The live provider integration was not exercised as part of automated tests.
