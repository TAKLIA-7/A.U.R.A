# Security model

The only database execution functions are registered in `TOOL_SCHEMAS`; tool arguments use Pydantic with extra fields forbidden. Filter and export-field names are allowlisted. Queries use SQLAlchemy expressions and bounded result limits. The database contains synthetic names and `.invalid` email addresses.

Protected mode validates first, sends schema-valid actions to OpenRouter JEV by default, then applies deterministic hard vetoes. JEV receives the bounded, credential/identifier-redacted task text, validated proposed tool and arguments, tool purpose, data classification, public/sensitive field lists, configured row caps, recent tool names, thresholds, and enforcement invariants. It does not receive database query results, credentials, or raw record identifiers. A JEV recommendation is stored separately from AURA's final decision. Engine failure is represented as a fail-closed block. The interactive agent commits the correlated action and pre-execution lifecycle audit events before calling the executor; a failure to commit that decision record prevents execution. An execution outcome is appended after the call. Sensitive fields are denied in protected exports. Two preceding reads make a subsequent export fail with `SEQUENCE_EXPORT`. Baseline intentionally permits the registered export tool and records sensitive exposure counts without persisting returned values.

Monitoring records include action and trace identifiers, decision/risk fields when available, measured JEV decision latency, execution outcome, and a correlated lifecycle timeline. Alerts are derived from actual stored blocks, JEV failures, and repeated blocks within a session trace. CSV export is bounded and its creation is audited. Records are append-only through current application routes, but are not tamper-evident and have no retention/deletion policy.

Structured agent logs expose indexed event name, severity, action/trace IDs, agent/tool identifiers, separate JEV and AURA decisions, risk, and execution status. The detail view returns only persisted event metadata and the sanitized detail payload; tool arguments must continue to use the existing redaction path. Severity reflects event urgency: a policy block is a warning, while provider or execution failure is an error. `decision` never implies execution; only a success lifecycle event records `SUCCESS`. Legacy SQLite databases receive additive columns and indexes at startup. Existing older events remain available with inferred display labels but are not backfilled into indexed fields.

Natural-language query tests are explicitly started through a separate test-run API protected by a shared `AURA_TEST_RUN_TOKEN`. Each query uses the existing protected agent gateway; it cannot invoke the executor directly or supply arbitrary SQL. The seeded database contains fictional customers only, and the catalog is read-only. Scenario definitions/results are stored separately from production events, while related action/audit events are tagged with `test_run_id`; production monitoring excludes those test actions. Test reports store redacted arguments and execution counts, never model response text or returned customer field values. The shared token is only a local operator gate and does not provide user identity, reviewer roles, or production access control.

This is a local MVP. Authentication, role-based reviewer authorization, authenticated agent/session identity, multi-tenant isolation, and production-grade durable/tamper-evident audit storage are not implemented. Approval actions can execute registered synthetic-data tools and must not be exposed on an untrusted network. JEV integration is configured through OpenRouter's Decisions API; provider live verification status is reported by `/api/health` and must not be inferred from mocked tests. General prompt-injection resistance is not established.
